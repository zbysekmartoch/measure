# Verze 0.5.1

**Datum vydání:** 2026-10-09

## Paměťová ochrana workflow (memory guard)

Každý krok workflow nyní běží pod dohledem paměti, aby jeden skript nemohl vyčerpat RAM celého serveru.

### Co se změnilo

- **Čekání na volnou paměť** — krok se nespustí, dokud nemá systém dostatek volné RAM (výchozí 20 % celkové paměti). V panelu průběhu se zobrazí stav ⏳ *Waiting for free memory* s aktuálními čísly.
- **Strop na jeden skript** — skript běží v cgroupu s pevným limitem (výchozí 90 % RAM, bez swapu). Když ho překročí, ukončí ho jádro místo toho, aby se celý server zahltil swapováním.
- **Výjimka přes vykřičník** — skript, který má v názvu `!` (např. `tezky_model!.py`), běží bez stropu; jeho RSS se jen zobrazuje.
- **Živá spotřeba paměti** — u běžícího kroku je vidět aktuální RSS, po doběhnutí peak (▲). Peak se zapisuje i do `output.log`.
- **Vysvětlený pád** — každý neúspěšný krok má v `output.err` řádek `[measure] Step N … FAILED after X s: <důvod>`. Zabití bez tracebacku je označeno jako pravděpodobné vyčerpání paměti včetně peaku a limitu; exit kód 139 jako segfault v nativní knihovně.

### Záložka Performance

- Nové karty **System memory used**, **Swap used** a **Running workflow scripts**.
- Graf **System memory used** (celý stroj, ne jen Node proces).
- Tabulka **Workflow runs (memory guard)** s aktuálním krokem, stavem, RSS a peakem každého běžícího workflow a s informací, zda je aktivní tvrdý cgroup limit.

### Konfigurace

Blok `resources` v `backend/config.json` (nebo proměnné prostředí `SCRIPT_MAX_MEMORY_MB`, `SCRIPT_MIN_AVAILABLE_MB`, `SCRIPT_USE_CGROUP`…). Podrobnosti ve `WORKFLOW.md`, sekce *Memory Guard*.

## Obnova stavu po reloadu stránky

Prohlížeče uvolňují karty na pozadí při nedostatku paměti (Firefox *tab unloading*, Chrome *Memory Saver*); po návratu se stránka načte znovu a dosud se ztratilo všechno otevřené.

- Otevřené laboratoře, aktivní záložka, podzáložka v laboratoři (Scripts / Results / Chat / Settings) a otevřené soubory se po načtení stránky obnoví.
- Neuložené změny v editoru se průběžně ukládají do prohlížeče a po obnovení se vrátí do editoru (soubor zůstane označený jako neuložený). Pokud se soubor mezitím změnil na serveru, koncept se zahodí a zobrazí se upozornění.
- V záložce **Performance** je tabulka *Page loads of this browser tab* s typem načtení a vysvětlením — reload v době, kdy byla karta skrytá, znamená uvolnění karty prohlížečem.

## Nová debugging session se rovnou otevře

Po kliknutí na 🛠 *Create new debugging session* u workflow se aplikace sama přepne na záložku **Debug** a nově vytvořenou session rovnou vybere. Dosud bylo nutné přepnout záložku a session vyhledat v seznamu ručně.
